# Video Studio authored keyframed mask runtime

Chat 3 Wave 8 extends the existing professional Video Studio grouped compositor with authored mask animation. It is a manual/keyframed rotoscoping capability. It does **not** claim automatic subject segmentation, AI rotoscoping, planar tracking, point tracking or motion tracking.

## Supported authored mask animation

Video clips can animate the existing `EditorMask` model without introducing another project schema. The supported keyframe paths are:

- `points` — normalized mask control points in the existing 0..1 source coordinate space;
- `opacity` — bounded 0..1;
- `feather` — bounded to the existing mask model range;
- `expansion` — bounded to the existing mask model range.

Existing shapes remain supported:

- rectangle;
- ellipse;
- polygon;
- path.

Existing mask composition also remains unchanged:

- add;
- subtract;
- intersect;
- inversion;
- feather;
- expansion;
- opacity.

`hold`, `linear`, `smooth` and `bezier` keyframe interpolation names use the same bounded interpolation conventions as the existing professional editor. Smooth/bezier currently use the established smooth-step interpolation contract rather than claiming arbitrary cubic handle evaluation.

## Point topology rule

Interpolated `points` keyframes must keep the same number of control points between adjacent frames. This lets corresponding points move deterministically without guessing vertex correspondence.

A deliberate topology change is allowed only across a `hold` segment. If point counts differ across a linear/smooth/bezier segment, export fails closed.

## Sequence-time alignment

Mask keyframes are authored in editor sequence time. Transient source derivatives are produced before the grouped compositor applies clip speed/reverse, so Wave 8 maps derivative time back to sequence time:

- normal clip: `sequence_time = item.start + derivative_time / speed`;
- reversed clip: `sequence_time = item.start + item.duration - derivative_time / speed`.

The result is bounded to the clip's authored sequence interval. This keeps mask motion aligned with the final timeline rather than accidentally following derivative-local time.

## Render path

Static masks continue to use a project-local grayscale mask asset. When at least one enabled mask is keyframed, the runtime:

1. probes the source video dimensions and usable frame rate;
2. evaluates all enabled masks for each derivative frame using Pillow and the existing mask compositor;
3. streams grayscale matte frames to FFmpeg through a raw-video pipe rather than writing a directory of per-frame PNGs;
4. extracts any alpha already present in the visual source;
5. multiplies that alpha by the authored mask matte;
6. merges the combined alpha back into the picture;
7. writes the transient masked derivative as lossless QuickTime RLE (`qtrle`) ARGB;
8. delegates final timeline/group/track composition to the established compositor;
9. removes transient work media after export.

The alpha multiplication is deliberate. A Wave 7 chroma-keyed clip may already contain transparent pixels; replacing its alpha with a mask would incorrectly restore keyed background pixels. Multiplication preserves both the chroma matte and the authored roto matte.

## Source and privacy boundary

- source media is never mutated;
- mask frame generation is local to the render process;
- no mask frames are uploaded to an external provider by this runtime;
- transient derivatives remain within the project work directory and are removed after export;
- export metadata records that keyframed masks were executed and that source media remained immutable.

## Explicit fail-closed boundary

The following remain unsupported by this wave:

- non-empty `EditorMask.tracking` data / automatic tracked masks;
- keyframed mask paths other than `points`, `opacity`, `feather` and `expansion`;
- interpolated point-topology changes without `hold`;
- keyframed masks on non-video items;
- any claim that authored keyframes were generated by an automatic tracker.

When these states are encountered, rendering fails closed instead of flattening, dropping or pretending to execute them.

## Validation evidence

Regression coverage includes:

- numeric and point interpolation;
- sequence-time speed/reverse mapping;
- fail-closed unsupported paths;
- fail-closed automatic tracking data;
- topology-change validation;
- a real FFmpeg early/late-frame render proving an authored rectangle moves across the picture;
- source SHA-256 immutability;
- transient cleanup;
- a real chroma-key + authored-mask integration render proving existing alpha and mask alpha are multiplied rather than replaced;
- production render API routing through the keyframed-mask compositor.

This is source-side execution evidence. It does not replace representative production-device acceptance testing or establish an automatic tracking capability.
